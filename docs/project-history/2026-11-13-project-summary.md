## 1. 專案概況

專案已從個人網站的基礎搭建，逐步發展為包含文章發布、個人收藏展示、專題整理，以及 Word 文件轉換工具的個人內容平台。

1. 建立可長期維護、可自由擴充的 Astro 個人網站。
2. 建立以 Word 為寫作入口、能自動產生 Markdown／MDX 文章結構的發布流程。

## 3. Word-to-MDX 轉換器成果

程式位置：`scripts/word-to-mdx.py`

轉換器的目標，是將 Word 文件轉換為 Astro 內容集合可使用的 Markdown 或 MDX 文件，並自動建立文章目錄、Frontmatter 和圖片資源。

### 3.1 基礎功能

目前已支援：

- 讀取 `.docx` 文件。
- 使用 Word 檔名生成文章標題。
- 中文檔名轉拼音並生成 slug。
- 生成 Frontmatter。
- 建立文章目錄及 `images` 子目錄。
- 擷取 Word 文件中的圖片。
- 根據指定元件自動選擇 `.md` 或 `.mdx`。
- 檢查整個文章目錄是否已存在，避免覆寫或混入舊檔案。
- 轉換失敗時清理本次建立的文章目錄。

### 3.2 文字與格式

目前支援一般段落、Word 標題樣式、手動編號標題、粗體、斜體、底線、刪除線、超連結、有序及無序清單、巢狀清單、引用段落、表格及表格內換行。

連續編號的標題可以轉換為 Markdown 標題；普通有序清單則維持清單形式。

### 3.3 圖片處理

已測試的圖片情境包括：

- 同一段落內文字與圖片混排。
- 同一段落內多張圖片。
- 圖片位於段落開頭或結尾。
- 獨立圖片段落。
- 圖片說明位於上方或下方。
- 圖片與說明文字之間有其他文字。
- 浮動圖片及多張浮動圖片。
- 連續圖片。
- 不同尺寸及方向的圖片。
- 空白段落前後的圖片。
- 相同圖片重複插入。

目前可以保留圖片及文字內容順序；相同圖片重複使用時，只會擷取一份實體圖片檔案。

### 3.4 MD／MDX 自動判斷

目前會檢查以下元件：

- `Figure`
- `ImageGallery`
- `ImageCompare`
- `ImageLightbox`
- `HeaderLink`

使用正規表達式辨認元件標籤，避免把名稱相似但不同的標籤誤判為元件。已完成 25 組形式測試。

### 3.5 Slug 與資料夾保護

中文檔名會轉為拼音 slug；英文、數字及底線等也會進行正規化。

若文章目錄已存在，轉換器會中止，不會覆寫既有內容。轉換期間若發生例外，會清理本次建立的文章目錄，避免留下不完整輸出。

### 3.6 錯誤處理

已處理或測試的情況：

- 找不到輸入檔案。
- 不支援的檔案格式。
- 日期格式錯誤或日期不存在。
- 描述欄位只有空白。
- 輸出文章目錄已存在。
- 轉換中途發生例外及自動清理。

轉換器的日期與描述參數為必要參數。執行時必須提供 `--date` 和 `--description`。

## 4. 測試與整合驗證

### 4.1 綜合回歸測試

固定測試文件：

`Word-to-MDX_綜合回歸測試文章.docx`

測試涵蓋 Frontmatter、標題、正文、文字格式、超連結、巢狀清單、編號標題、引用、表格、圖片、圖片說明、分頁符號、分節符號及文件末尾內容。

主要項目已通過。

### 4.2 圖片混排測試

另有 15 組圖片混排及錨定情境測試，包含普通圖片、浮動圖片、重複圖片和不同尺寸圖片。已逐項確認結果符合目前設計預期。

### 4.3 錯誤處理測試

已實際測試不存在的 DOCX、不支援格式、錯誤日期、空白描述、既有文章目錄，以及轉換途中刻意觸發例外的清理行為。

### 4.4 Astro 建置

加入測試文章時，Astro 建置成功，產生 20 個頁面。移除測試文章後再次建置成功，產生 19 個頁面。

這證明轉換器輸出可以被 Astro 正常識別及建置。

## 6. 尚待整理的事項與已知限制

### 6.1 尚待完成或改善

| 項目 | 現況 | 建議優先程度 |
|---|---|---|
| 轉換器使用說明 | 尚未整理成完整文件 | 高 |
| 程式碼及診斷輸出整理 | 可再檢查是否有不需要的診斷程式碼 | 中 |
| 更多 MDX 元件支援 | 目前只有指定的五個元件 | 中 |
| 更完整的錯誤提示 | 非預期錯誤仍可能顯示 traceback | 低 |
| 更多特殊 Word 格式測試 | 尚未全面測試所有特殊格式 | 低 |

### 6.2 已知且目前接受的限制

| Word 功能 | 目前處理方式 |
|---|---|
| 分頁符號 | 忽略頁面布局，保留正文內容 |
| 分節符號 | 不保留頁面布局 |
| 浮動圖片 | 轉為獨立圖片區塊 |
| 圖片環繞文字 | 不還原原始環繞方式 |
| 圖片錨定位置 | 不保留 Word 錨定資訊 |
| 頁首頁尾 | 不作為文章正文轉換 |
| 頁面邊距及方向 | 不保留 |

這些是目前刻意接受的取捨，不是現階段的核心阻塞問題。轉換器的主要目標是保留網站文章所需的文字、圖片及內容順序，而不是完整複製 Word 的排版系統。

SmartArt、複雜圖表、特殊文字框、數學公式、複雜合併儲存格及內嵌物件等，尚未全面支援或驗證。應在實際遇到需求時再評估是否增加。

## 7. 後續開發路線

建議按階段推進，不要同時大幅修改轉換器、網站及展示系統。

### 第一階段：整理現有轉換器

優先事項：

1. 編寫使用說明。
2. 記錄必要命令參數及完整操作流程。
3. 整理程式碼註釋。
4. 檢查並清理不再需要的診斷輸出。
5. 記錄已知限制及測試範圍。

這個階段以整理為主，避免大幅改動已通過測試的核心邏輯。

### 第二階段：改善文章發布流程

可逐步評估：

- 指定文章分類，例如博客或隨筆。
- 更靈活地指定封面圖片。
- 支援更新日期。
- 指定輸出目錄。
- 提供更完整的轉換結果摘要。
- 增加轉換前預檢查，提示可能無法完整轉換的內容。

### 第三階段：擴展網站內容與展示

建議方向：

- Steam 收藏、已下架遊戲及統計資料展示。
- Galgame 收藏整理。
- PS2、PS3、PSP 等實體遊戲收藏展示。
- 專題頁面的長期資料整理與追蹤。

### 第四階段：擴展網站能力

可在有實際需求時增加：

- 文章標籤系統。
- 文章搜尋及分類篩選。
- 文章目錄及閱讀進度。
- 收藏資料排序與篩選。
- 更完善的手機版布局。
- RSS 訂閱。
- 相關文章推薦。
